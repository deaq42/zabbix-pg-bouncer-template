# PgBouncer для Zabbix 6.0

Комплект: `Template PgBouncer Zabbix 6.0.xml`, `pgbouncer.sh`, `pgbouncer.conf`.
Шаблон называется **Template PgBouncer by agent 6.0** и может быть импортирован
рядом с исходным шаблоном. Для одного хоста используйте только один из них:
совпадающие ключи элементов не позволяют привязать оба одновременно.

Проверяемая конфигурация: Zabbix Server 6.0.48, Agent 6.0.49, PgBouncer 1.26.1.
Для сборщика нужны Bash и psql версии 12 или новее (`--csv`). Дополнительные
Python/JSON-утилиты на хосте мониторинга не нужны. Другие версии PgBouncer
в этой проверке не запускались; именованные поля могут отсутствовать в старых версиях.

## Установка

1. В PgBouncer добавьте отдельного пользователя мониторинга в auth-файл
   и в `stats_users` (добавьте к существующему списку, если он уже есть):

   ```ini
   stats_users = zabbix
   ```

   В `userlist.txt` добавьте учётные данные в формате, совместимом с вашим
   `auth_type`. Пользователю нужны только права статистики; `admin_users` не требуется.
   Примените конфигурацию штатным способом.

2. Установите файлы для классического Zabbix Agent:

   ```bash
   sudo install -d -o zabbix -g zabbix /var/lib/zabbix/externalscripts
   sudo install -o root -g root -m 0755 pgbouncer.sh /var/lib/zabbix/externalscripts/pgbouncer.sh
   sudo install -o root -g root -m 0644 pgbouncer.conf /etc/zabbix/zabbix_agentd.d/pgbouncer.conf
   ```

   Для Agent 2 используйте `/etc/zabbix/zabbix_agent2.d/` и его сервис.
   Agent 2 отдельно не запускался в этом тесте; UserParameter стандартный.
   Убедитесь, что основной конфиг агента включает выбранный каталог.
   Удалите старые UserParameter с этими ключами, если они уже установлены.

3. Для домашнего каталога пользователя `zabbix` `/var/lib/zabbix` создайте
   `.pgbouncer.env` (без пароля):

   ```bash
   PGHOST=127.0.0.1
   PGPORT=6432
   PGUSER=zabbix
   PGCONNECT_TIMEOUT=3
   ```

   И `.pgpass`, заменив пароль своим:

   ```text
   127.0.0.1:6432:pgbouncer:zabbix:REPLACE_WITH_MONITOR_PASSWORD
   ```

   Установите права:

   ```bash
   sudo chown zabbix:zabbix /var/lib/zabbix/.pgbouncer.env /var/lib/zabbix/.pgpass
   sudo chmod 0600 /var/lib/zabbix/.pgbouncer.env /var/lib/zabbix/.pgpass
   ```

   Если `HOME` агента отличается, используйте его настоящий домашний каталог
   (его можно узнать через `getent passwd zabbix`). Сборщик читает
   `$HOME/.pgbouncer.env`, libpq — `$HOME/.pgpass`.
   Можно задать путь через `PGBOUNCER_CONFIG`, а к паролям — через `PGPASSFILE`.
   Стандартные переменные libpq, включая настройки TLS, передаются в psql.
   Не включайте shell tracing: конфигурация может содержать чувствительные данные.

4. Поставьте `Timeout=10` в конфигурации агента и перезапустите сервис:

   ```bash
   sudo systemctl restart zabbix-agent
   sudo -u zabbix -H /var/lib/zabbix/externalscripts/pgbouncer.sh pools
   ```

   Ожидается CSV с первой строкой, начинающейся с `database,user,`.
   При ошибке подключения сборщик возвращает ненулевой код, без данных в stdout.
   Команда `discover` также возвращает CSV; преобразование в LLD делает шаблон.

5. В Zabbix 6.0 откройте **Configuration → Templates → Import** и импортируйте
   `Template PgBouncer Zabbix 6.0.xml`. Привяжите **Template PgBouncer by agent 6.0**
   к хосту с агентом. Проверьте его агентский интерфейс и разрешение запросов
   сервера в `Server=`.

   При замене старого шаблона сначала отвяжите его. Действие **Unlink and clear**
   удаляет старые элементы и их историю; выбирайте его только если история не нужна.
   Обычный **Unlink** сохраняет элементы и требует отдельного плана миграции
   совпадающих ключей. Для безопасной первой проверки используйте отдельный хост.

## Что исправлено

- CSV преобразуется в JSON с именами столбцов. Номера столбцов не используются.
- Пулы обнаруживаются по базе и пользователю; статистика баз — один раз на базу.
  В список баз попадают базы, появившиеся в `SHOW STATS`.
- Все длительности хранятся в секундах (`microseconds × 0.000001`).
- Скорость изменения применяется только к накопительным счётчикам; тип FLOAT
  сохраняет дробные запросы/сек и байты/сек.
- Проверка CSV-заголовков выполняется до преобразования: сообщение об ошибке
  агента не превращается в успешное пустое discovery.
- Потерянные ресурсы сохраняются 7 дней; корректная пустая таблица допустима.
- Нулевые лимиты не вызывают тревог о заполнении. Клиенты сравниваются с
  `max_client_connections`, серверные подключения — с `max_connections`.
- Сохранены графики, dashboard и пороги, совместимые с Zabbix 6.0.

После первого запуска нужно дождаться двух сборов (интервал 30 секунд), чтобы
появились скорости счётчиков. Расчётный общий maxwait обновляется раз в минуту.
Сырые данные хранятся 1 час для диагностики, численные метрики — 30 дней.

Макросы порогов: `{$PGBOUNCER.WAIT.TIME}` и `{$PGBOUNCER.POOLS.MAXWAIT.TIME}`
в секундах, `{$PGBOUNCER.CL.CONN.WARN}` и `{$PGBOUNCER.DB.CONN.WARN}` в процентах.
Возможны значения с контекстом имени базы.
